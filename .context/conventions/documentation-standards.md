# Documentation Standards

## Documentation Rules

- Keep client-facing documents clear and professional.
- Keep internal engineering notes explicit about assumptions and TODOs.
- Do not hide critical rules only in linked files; repeat non-negotiables in `AGENTS.md` and `CLAUDE.md`.
- Every future phase plan must include scope, non-scope, acceptance criteria and validation commands.
- Document unresolved business and financial rules instead of encoding assumptions.

## File Naming

- Use clear markdown names.
- Use numbered plan files only when sequence matters.
- Keep templates in `docs/plans/`.
